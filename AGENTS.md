# Architecture rules
- Fiscality and commissions share the same paginated commission source; retain original records and persist incremental receipts separately, never infer cash from paid status or client order revenue.
- Resolve fiscal ownership through dated mandates and explicit historical corrections; subject-wide annual tax and INPS calculations precede local filters, and Enasarco limits group by subject and agency relationship.
- Fiscal calculations return unavailable results for unverified mandatory inputs; declared references, liabilities, paid cash, and deductible verified contributions remain separate.
- Keep commercial proposals isolated from operational prices and conditions until the owner-authorized, row-locked acceptance RPC commits once; preserve accepted snapshots/PDFs and normalize explicit price units/IVA into the existing per-piece price source.
- Use the existing private document archive for proposal PDFs and references with explicit company/customer/year metadata; shared archive views must read the same records.
- Use the shared header-order pair engine for Home, Riordino and reorder alerts, paginating all valid commercial dates; product forecasts remain a separately labelled drilldown.
- Use the canonical metrics engine for economic inclusion, order dates and saved revenue; audits must not alter commercial records.
- Share paginated read-only order loading between the data panel and order audit so comparisons cover the complete archive.
- Keep document comparison local and explicit: read PDF text with PDF.js and require the user to enter declared totals and matching period, preventing invented extracted values or accidental order imports.
- Keep global internal search in MainLayout and use authenticated database reads, so every CRM page has the same search access without bypassing permissions.
- Derive installable icons and favicon from the existing agency logo; keep home-screen support manifest-only without adding offline caching.
- Keep sidebar color pairs in global CSS, not theme-specific background overrides, to preserve readable contrast in every theme.
- Orders list shows a table from xl width and compact cards below it; both read the same OrdiniTableRow data so actions stay identical.
- Send order PDFs through the agency Gmail connector server-side with an authenticated owner-scoped snapshot and unique persisted attempt ID; immutable PDF copies and outcome records prevent silent stale attachments and duplicate retries.
- Share proforma PDF capture between downloads and email attachments, reloading the order before capture and checking its snapshot version before Gmail submission.
- Encode order email MIME and PDF bytes in bounded chunks without per-byte arrays, so large attachments stay within the email function memory budget.

- Persist proposal removal separately from immutable accepted snapshots; retain accepted conditions and shared archive/image references.
- Match document identities from content against accessible records; manual association status is authoritative and must survive reanalysis.
- Document archive is an active memory: virtual per-company folders (never physical paths), `documenti_aziende` links for multi-company visibility, verified aliases in `aziende_alias` learned from manual corrections, and `stato_elaborazione` as the single processing state.
- Generate dedicated poster exports from saved proposal content, awaiting real image decoding and preserving aspect ratio.
- Mirror OneDrive physical hierarchy by stable drive/item IDs in a server-managed index; keep CRM classification virtual, persist every delta checkpoint, and gate shared-connector access through an explicit allowlist.
- All reorder consumers use the same eligibility and chronological cadence replay; exclude explicitly reconstructed revenue allocations from chronology only, preserve historical baseline, adapt operational cadence after repeated shifts, and expose original IDs and exclusions without modifying commercial records.
- Agency members share one data owner: rows are rewritten to the owner by trigger and read through member-to-member RLS, while the acting user is kept in created_by/updated_by/sent_by, so colleagues see the same archive without losing authorship.
- Staff sign in by case-insensitive username through the agency-auth function mapped to internal auth identities, so no email is needed and lockout is enforced server-side.
- Order drafts live in their own table and become orders only on explicit save, so they never enter KPI, statistics, reorder or commissions.
- Order recipients come from the per-company address book and the single agency sender is enforced in the email function, so no client setting can send from another mailbox.
- Order form and proforma share one cartons/pieces/gifts calculation and rows snapshot pieces-per-carton at sale, so later catalog edits cannot change past documents.
- Product statistics are computed by database functions that allocate saved order totals over net non-gift rows, so product sums reconcile with order revenue and missing detail is reported separately.
- Notifications are written once per event by database triggers/jobs into a per-user outbox, then fanned out to every enabled Web Push device by a scheduled dispatcher, so history, dedupe and retries never depend on the browser that triggered them.
- Reorder alerts run the same shared reorder engine and the owner-level tolerance setting as the Riordino page, so alerts and the page always agree.
